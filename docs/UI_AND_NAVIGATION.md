# UI/UX, навигация и основной экран «Свежие» (`Android` + `Windows`)

Этот документ фиксирует визуальные стандарты и правила навигации **Help-CSL**, обеспечивающие единый аккуратный интерфейс на мониторах Windows и экранах смартфонов Android.

---

## Рабочие окна и контраст

Рабочие окна и диалоги приложения Windows занимают доступную область монитора владельца с учётом панели задач (не эксклюзивный полноэкранный режим). Закрываются крестиком или Esc; системные файловые диалоги и уведомления управляются ОС. Вкладки инструментов переносятся на несколько строк. Текст не должен наследовать чёрный цвет на тёмной поверхности: корень темы задаёт цвет `onSurface`, а кнопкам с явно заданным фоном задаётся соответствующий цвет текста. В настройках доступны дополнительные палитры «Спокойная светлая» и «Спокойный сланец»; выбор не сбрасывает остальные параметры.

## 1. Фирменная палитра `csl.by`

| Токен | Цвет | Назначение |
|---|---|---|
| `CslMidnight` | `#04091E` / `#0F172A` | Верхняя шапка навигации, контрастные тёмные плашки |
| `CslOrange` | `#F7631B` | Главный фирменный акцент `csl.by`: активная вкладка, кнопка «▶ В работу», создание тикета, вертикальная полоска `4dp` в логотипе |
| `StatusGreen` | `#16A34A` / `#2EB85C` | Индикатор **«● Свежие»**, выполненные заявки, онлайн-статус и норма SLA `< 15 мин` |
| `StatusBlue` | `#2563EB` | Очередь и бейджи статуса **«В работе»** |
| `StatusAmber` | `#D97706` / `#E65100` | Индикатор **«◷ Прошлые»** (зависшие заявки с прошлых дней), ожидание `15–45 мин` |
| `StatusRed` | `#DC2626` / `#D93025` | Просрочка SLA `> 45 мин`, аварии Zabbix `Disaster (5)`, вкладка аудита «🗑 Удалённые» |

Обе платформы поддерживают **Светлую** и **Тёмную** темы с переключением в 1 клик прямо из верхней панели.

## 2. Контракт основного экрана «Свежие» (при старте и по кнопке «Назад»)

Это базовое правило навигации программы на обеих платформах:

### 2.1. Что открывается при запуске программы
- Верхняя/нижняя вкладка раздела: **«Заявки»** (`TICKETS`).
- Вкладка очереди: **«Новые»** (`TicketTabMode.NEW` / `TicketQueueTab.NEW`).
- Возрастной подфильтр: **«● Свежие»** (`TicketAgeFilter.FRESH_TODAY` — обращения, созданные с `00:00` текущих суток по `Europe/Minsk`).
- Если за сегодня свежих заявок пока `0`, а с прошлых дней есть неразобранные тикеты, над пустым состоянием выводится компактная однострочная подсказка **`● В прошлых заявках: N ──── Показать →`**, позволяющая перейти к старым тикетам в 1 клик, не загромождая утренний рабочий экран.

### 2.2. Поведение кнопки «Назад» на Android
Реализовано в `MainActivity.kt`, `MainViewModel.kt` и `TicketsScreen.kt`:
1. **Из открытой карточки заявки (`TicketDetailScreen`)**: нажатие стрелки `←` в шапке или системного жеста `Back` вызывает `viewModel.closeTicketDetail()` → закрывает тикет и переводит главный экран в состояние **«Заявки → Новые → ● Свежие»**.
2. **С любой другой нижней вкладки (`Zabbix`, `Ремонт`, `Wiki`, `Чат`, `Настройки`)**: системный жест `Back` перехватывается `BackHandler` в `MainActivity.kt` и возвращает пользователя на **«Заявки → Новые → ● Свежие»** *(если внутри `Wiki` открыта статья, первое нажатие `Back` закрывает статью к списку раздела, второе — возвращает на «Свежие»)*.
3. **Внутри экрана «Заявки»** (если открыта вкладка `В работе`, `Закрытые`, `Сервисные`, подфильтр `Прошлые` или `Все`, введён поисковый запрос или включён мультивыбор): системный жест `Back` сбрасывает вид обратно на **«Новые → ● Свежие»**.
4. **Когда пользователь уже находится на «Заявки → Новые → ● Свежие»**: все внутренние `BackHandler` отключены (`enabled = false`), и повторное нажатие `Back` штатно сворачивает приложение на рабочий стол Android.

### 2.3. Поведение кнопки «Назад» на Windows Desktop
Реализовано через `controller.isAtFreshHome()` и `controller.navigateBackToFreshHome()` в `DesktopController.kt`, `Main.kt` и `DesktopTicketViews.kt`:
- Возврат на основной экран **«Заявки → Новые → ● Свежие»** (с закрытием открытой карточки тикета или статьи Habr и сбросом поисковой строки) срабатывает всеми привычными для Windows способами:
  1. Кнопка **`← Назад`** в левой части верхней навигационной панели (появляется автоматически, когда пользователь ушёл с экрана «Свежие»);
  2. Кнопка **`← Назад`** в шапке открытой карточки заявки (`DesktopTicketInspector`) и читалки Habr;
  3. Повторный клик по активной вкладке **`Заявки`** в верхней панели;
  4. **Боковая кнопка мыши «Назад»** (`MouseEvent.BUTTON4` / `XButton1`);
  5. Клавиатурные сочетания **`Alt + ←`** и **`Esc`** *(когда не открыто модальное диалоговое окно)*.

## 3. Правила гармоничной вёрстки плашек и панелей

1. **Единая высота сегментированных вкладок (`IntrinsicSize.Min` + `fillMaxHeight()`)**:
   - Четыре вкладки очередей (`Новые`, `В работе`, `Закрытые`, `Сервисные`) всегда содержат ровно две сбалансированные строки (название + счётчик) и выровнены по общей высоте контейнера без перекосов.
2. **Отсутствие многоэтажных рамок перед списком заявок**:
   - Между переключателем `Все | ● Свежие | ◷ Прошлые` и первой карточкой тикета используется лёгкий **однострочный разделитель секции** (`● Свежие заявки (N) ──── за сегодня`), а не массивные вложенные карточки с рамками.
3. **Устойчивость к увеличенному системному шрифту Android (`fontScale` до `1.35x`)**:
   - В компактных пилюлях, табах и шапках шрифт привязывается через `with(LocalDensity.current) { X.dp.toSp() }` с `maxLines = 1` и `softWrap = false`, чтобы подписи (`Все`, `Свежие`, `Прошлые`, `Сисадмин`) никогда не переносились по одной букве.
4. **Запрет серых горизонтальных скроллбаров под кнопками на Windows Desktop**:
   - Группы кнопок действий в инспекторе тикета, на стартовом дашборде и в настройках верстаются через `Row` с весами или адаптивный `FlowRow`, чтобы все кнопки органично вписывались в ширину карточки без полос прокрутки.
