# Полный гайд по программе Help-CSL (Android APK + Windows `setup.exe`)

**Help-CSL** — кроссплатформенное рабочее место дежурного и выездного системного администратора службы технической поддержки (**Android `.apk`** и **Windows 10/11 `setup.exe`**) в фирменном корпоративном стиле **`csl.by`** (`#04091E` + `#F7631B`).  
Поддерживает как корпоративные серверы **Jira Server / Data Center** (REST API v2), так и облачную **Jira Cloud / Jira Service Management** (REST API v3).

> Актуальная версия документации: **Help-CSL v1.0.70** *(полная архитектурная и инженерная документация также структурирована в [`AGENTS.md`](AGENTS.md) и папке [`docs/`](docs/INDEX.md); встроенная интерактивная копия с поиском доступна прямо внутри Android и Windows версий по кнопке **«📖»** в верхней панели).*

### Сценарии первичной диагностики

Откройте **«🛠 Инструменты» → «📋 Сценарии»** и выберите «Сеть / DNS», «Домен / AD», «Принтер», «Диск / место» или «Служба / сервис». Укажите симптомы, время и влияние, пройдите нужные шаги и для каждого отметьте «Не проверено», «Норма», «Есть проблема» или «Не применимо»; при необходимости добавьте результат и дальнейшие действия. В карточках команд указаны назначение, место и способ запуска, права и риски. Команды копируются отдельно; приложение их не выполняет. Итог копируется вручную для вставки в заявку Jira, автоматической отправки нет.

Черновики сохраняются при переключении сценариев и вкладок пока окно инструментов открыто; на Android состояние также рассчитано на поворот экрана. При закрытии окна или завершении приложения черновик может быть потерян — заранее скопируйте итог. Очистка конкретного сценария требует подтверждения. Не вводите пароли и секреты; перед копированием и публикацией удалите конфиденциальные сведения. Для контроллера домена тест защищённого канала члена домена не подходит; восстановление доверия не запускается из сценария.

### Карточка диагностики домена AD

В **«🛠 Инструменты» → «🏢 Домен AD»** выберите место выполнения: проблемный доменный ПК/рядовой сервер, контроллер или административный компьютер с RSAT. Роль выбирает инженер; приложение её не определяет и не подключается к AD. Карточка показывает подходящие проверки с точкой запуска, правами, ограничениями и кнопками копирования команды или инструкции. Для контроллера предлагается в том числе `dcdiag /test:DNS /DnsBasic /v`: полный `/DnsAll` может включать тест динамического обновления с записью в DNS.

Для члена домена отдельно доступно копирование скрипта восстановления защищённого канала. Сначала проверьте сеть/DNS/время, локальный доступ и резервную копию, согласуйте работы и отметьте все условия, затем подтвердите **только копирование**. Приложение не выполняет скрипт. При ручном запуске на целевом устройстве скрипт допускает только проверенные роли рядового члена домена, запрашивает `YES` и открывает системный запрос учётных данных с делегированными правами. Не применяйте его на контроллере домена; при сбоях репликации или сомнениях передайте проблему специалисту AD. После ремонта повторно проверьте канал и вход. На Android команда копируется в буфер телефона, не на целевой компьютер.

### Консольные команды и PowerShell

Откройте **«🛠 Инструменты» → «⌨ Команды»** на Windows или Android. Выберите Windows CMD, Linux / Bash или PowerShell, а также тему (например, «Домен / AD» или «Серверы»), либо найдите команду по названию, описанию или тексту. Раскройте карточку: в ней указаны назначение, как и где запускать, необходимые права и последствия. Нажмите **«Скопировать команду»** и вставьте содержимое в указанную оболочку на нужном компьютере или сервере. Кнопка «Скопировать инструкцию для коллеги» копирует пояснения вместе с командой — этот текст предназначен для передачи, а не для вставки в оболочку. На Android копирование производится в буфер телефона, а не на удалённый компьютер.

В теме **«Домен / AD»** есть диагностика контроллера, времени, GPO и защищённого канала, а также отдельное восстановление доверия для рядовых доменных компьютеров. Сначала проверьте корпоративный DNS, связь с контроллером и время, обеспечьте локальный административный доступ и согласуйте работы. Скрипт восстановления запрашивает подтверждение и доменные учётные данные отдельно; на контроллерах домена этот способ не применяется.

Приложение **не выполняет** команды самостоятельно. Адрес `example.com` в примерах замените на свой; для многострочных PowerShell-скриптов копируйте весь блок. Диагностика обычно ничего не меняет, но SFC, очистка кэша и перезапуск службы вносят изменения. Перед обслуживанием сервера проверьте резервные копии, зависимости и согласуйте окно работ; некоторые скрипты дополнительно требуют подтверждения `YES`.

В разделе **«🔌 Порты»** находится офлайн-справочник типовых портов и протоколов с поиском и копированием. Он не сканирует сеть и не является рекомендацией открывать порты.

В Android при небольшой высоте окна меню заявок и ремонта сворачиваются в кнопку «Открыть фильтры и поиск» / «Открыть управление и поиск»: нажмите её и прокручивайте панель, чтобы добраться до всех настроек. В справочнике команд и списке узлов прокручиваются и фильтры, и результаты. В коротком окне чата кнопка `#` открывает быстрые действия, а заметка смены доступна через значок закрепа.

## 1. Установка, обновления и быстрый старт за 3 секунды (QR-перенос)

### Первичная настройка вручную
1. Установите подписанный APK из [GitHub Releases](https://github.com/zigorminsk-debug/Helpdesk/releases).
2. Откройте вкладку **«Настройки»** и заполните блок **«Подключение к Jira»**:
   - **URL сервера Jira** — например, `https://jira.company.by` или `https://company.atlassian.net`.
   - **Тип сервера** — оставьте **«Автоопределение»** (либо явно укажите `Server / Data Center` или `Cloud`).
   - **Способ авторизации**:
     - `Логин + Пароль (Basic)` — классический вход для корпоративных Jira Server / DC;
     - `Email + API Token (Cloud)` — для облака Atlassian;
     - `Personal Access Token (PAT / Bearer)` — токен персонального доступа Jira DC.
   - Если ваш внутренний сервер использует корпоративный сертификат УЦ — включите **«Доверять самоподписанным SSL»**.
3. Нажмите **«Проверить подключение»**, убедитесь в зелёном статусе и нажмите **«Сохранить настройки»**.

### Настройка за 3 секунды с телефона коллеги (`Перенос QR`)
Чтобы новому сотруднику смены не вводить вручную URL сервера, правила фильтра, рабочие субботы РБ и шаблоны ответов:
1. На уже настроенном телефоне откройте **«Настройки» → «Перенос QR» → «Показать QR»**.
   - По умолчанию тумблер *«Включить мой логин и пароль/токен»* **выключен** — передаются только общие настройки команды, без личного пароля. При необходимости можно задать одноразовый PIN шифрования (`AES-GCM`).
2. На втором телефоне откройте **«Настройки» → «Перенос QR» → «Считать QR» → «📷 Сканировать QR-код камерой»**.
3. Все параметры сервера, графика РБ, шаблонов и фильтров применятся мгновенно — останется ввести только свой логин и пароль.

### Автообновление без потери настроек
Все релизы подписываются единым постоянным ключом `keystore/helpdesk-release.p12`. При выходе новой версии сверху появляется плашка **«Доступна версия v1.0.XX → Обновить»** (работает через Atom-ленту GitHub без лимитов `API 403`). Новая сборка ставится **поверх текущей** с сохранением всех настроек, досье клиентов и кэша.

## 2. Рекомендуемые разрешения телефона (особенно Xiaomi MIUI / HyperOS)

Чтобы уведомления о заявках приходили мгновенно даже на заблокированном экране:

2. **Контроль активности / Батарея** (на Xiaomi / Redmi / POCO / Huawei):

3. **Установка обновлений** — при первом автообновлении разрешите установку пакетов из `Help-CSL`.

## 3. Главный экран «Заявки»: вкладки, свайпы, фильтры, SLA и массовые действия

### Структура карточки заявки
Карточки спроектированы компактно без пустого пространства снизу и без обрезки важных кнопок (`...`):
- **Верхняя строка**: крупным жирным шрифтом отображается **Имя клиента / Организация** (`Сейлзмодерн`, `ЖКХ` и т. д.), справа — статус заявки.
- **Вторая строка**: компактный **номер тикета** (`CSL-37368`), категория портала JSM / тип задачи, **цветной SLA-индикатор ожидания** (`⏱ 12 мин`), исполнитель и значок вложений (`📎 2`).
- **Тема обращения** и панель телефонов + мессенджеров (`Telegram`, `Viber`, `WhatsApp`).

### 4 вкладки статусов
| Вкладка | Что попадает |
|---|---|
| **Новые** | Новые клиентские обращения (включая статус *«Ожидание поддержки»*), а также пересозданные по таймеру отложенные заявки. |
| **В работе** | Заявки, принятые инженерами в исполнение. |
| **Закрытые** | Решённые, выполненные и отклонённые обращения клиентов. |
| **Сервисные** | Автоматически отсеянные задачи мониторинга (`zabbix`, `prometheus`, боты, автоправила) с указанием причины фильтрации. Звук по ним **не подаётся**. |

### Быстрый фильтр по исполнителю
Под вкладками расположена полоса быстрого отбора со счётчиками:
- **Все** — вся очередь выбранной вкладки;
- **Мои** — заявки, назначенные лично на вас;
- **Свободные** — обращения без назначенного инженера.

### Жесты и ускорители на главном экране
- **Потянуть вниз (`Pull-to-Refresh`)** — мгновенный опрос Jira.
- **Свайп карточки ВПРАВО** → **«В работу»** (назначает тикет на вас и переводит статус).
- **Свайп карточки ВЛЕВО** → **«Позвонить»** клиенту (а если телефона в тикете нет — открывает обсуждение заявки во внутреннем чате админов).
- **Кнопка `📷` (Сканер S/N) в строке поиска** — открывает камеру, сканирует штрихкод / QR оборудования и ищет в Jira всю историю ремонтов по этому серийному номеру.
- **Кнопка `☑` (Массовый выбор) в строке поиска** — позволяет отметить сразу несколько карточек и одной кнопкой выполнить **«В работу»**, **«Коммент.»** или **«Закрыть»** для всей пачки.
- **Плавающая кнопка `+`** (справа внизу) — создание новой заявки с телефона с голосовым вводом `🎤` темы и описания.
- **Пустой экран очереди** — когда активных заявок нет, отображается плавная гифка из *«Компьютерщиков» (The IT Crowd)* с цитатой, а прямо под ней — живая лента свежих IT-статей с **`habr.com/ru`**.

## 4. Уведомления, график работы РБ, наушники, режим «За рулём» (TTS) и «Анти-шторм»

- **Действия прямо на пуш-баннере**: в уведомлении доступны кнопки **«В работу»** (принимает заявку в фоне без открытия экрана и останавливает сигнал), **«Позвонить»** и **«Открыть»**.
- **Производственный календарь Республики Беларусь (`Europe/Minsk`)**:
  - При включённом тумблере **«Рабочие дни»** звуковые оповещения и баннеры работают в будни `09:00–17:30` (время настраивается) с автоматическим учётом государственных праздников РБ, православной и католической Радуницы и официальных переносов рабочих суббот.
  - Заявки, пришедшие ночью или в выходной, не будят инженера, а аккумулируются и выдают сигнал ровно при открытии следующего рабочего окна.
  - В полях *«Доп. рабочие даты»* и *«Доп. выходные / отпуск»* можно добавить индивидуальные смены (`ГГГГ-ММ-ДД`).
- **Одновременный звук в наушниках и на динамике телефона (включая MIUI / HyperOS)**:
  - Если телефон лежит на столе с подключённой Bluetooth-гарнитурой, сигнал проигрывается **и в наушники, и через внешний динамик смартфона** (обходит подавление рингтона в Xiaomi HyperOS/MIUI). Можно выбрать один из 4 фирменных сигналов или свой MP3/рингтон.
- **Режим «За рулём» — голосовое чтение заявок (`TTS`)**:
  - Настройка *«Голосовое чтение новых заявок»* (`Выключено` / `Только в наушниках` / `Всегда`). Когда подключена гарнитура или Bluetooth автомобиля, через 2 секунды после мелодии синтезатор речи проговаривает: *«Новая заявка от ЖКХ. Не работает 1С»*.
- **Повторный сигнал по SLA**:
  - Если новую заявку никто из смены не взял в работу за `10 / 15 / 30 / 60 мин`, приложение отправит повторное напоминание.
- **Защита от «Шторма заявок»**:
  - Если упал провайдер или сервер и за один цикл прилетело сразу **3 и более** тикетов — вместо серии сирен прозвучит **один** сигнал со сводным уведомлением *«⚡ Шторм заявок: N новых обращений»*.

## 5. Карточка заявки: Workflow, отсрочка с пересозданием, коллеги и внутренние заметки JSM

Внутри открытой заявки доступны:
1. **Четыре основные кнопки движения по процессу**:
   - **«В работу»** — назначает заявку на ваш аккаунт Jira и переводит статус в исполнение.
   - **«Отложить на»** — выбираете дату и время в календаре (или вводите текстом): текущая заявка **закрывается с комментарием об отсрочке**, ставится точный системный будильник Android, и в назначенный час приложение **автоматически создаёт новую заявку** со всеми данными клиента, помещает её во вкладку `Новые` и присылает звуковой баннер.
   - **«Отклонить»** — запрашивает причину (текстом, голосом `🎤` или быстрым шаблоном) и переводит тикет в отклонённые.
   - **«Завершить»** — закрывает заявку с финальным комментарием и **автоматически возвращает вас на главный экран очереди**.
2. **Панель инженерных действий**:
   - **«👤 Коллеге»** — загружает список сотрудников проекта из Jira с поиском и передаёт заявку выбранному инженеру.
   - **«⏱ Worklog»** — списывает затраченное время (`5м / 10м / 15м / 30м / 1ч / 2ч`) в штатный журнал работ Jira.
   - **«✍️ PDF-акт»** — генератор акта выполненных работ с подписью клиента (см. раздел 7).
   - **«🔍 Скан S/N»** — сканирование серийного номера оборудования камерой.
   - **«💬 Обсудить заявку с админами в чате»** — переносит вас во внутренний чат с готовой кликабельной ссылкой на тикет.
3. **Безопасные комментарии JSM (`🌍 Ответ клиенту` ↔ `🔒 Внутр. заметка`)**:
   - Над полем ввода расположен явный переключатель:
     - **«🌍 Ответ клиенту»** — публичный комментарий, видимый заказчику;
     - **«🔒 Внутр. заметка»** — сохраняет комментарий со свойством `sd.public.comment = internal: true` (виден только агентам Jira Service Management).
   - Выше поля доступны **1-тап макросы быстрых ответов** (редактируются в «Настройках») и кнопка голосового ввода **`🎤`**.
4. **Вложения и камера (`📷 Сделать фото` / `📎 Прикрепить`)**:
   - Просмотр скриншотов из Jira с поддержкой масштабирования двумя пальцами (`Pinch-to-Zoom`), открытие `.pdf/.log/.docx/.zip` внешними программами и отправка фотографий с камеры (с автосжатием для быстрой загрузки по мобильной сети).
5. **«Анализ обращений»** — откройте любую заявку нужного клиента и раскройте блок. Выберите «Автор» или организацию из явно заполненного поля JSM Organizations, затем тему; нажмите на номер/название для перехода к исходной заявке. Доступны все темы и постраничное раскрытие результатов. Категории определяются ключевыми словами только в заголовках, один тикет может войти в несколько тем; это не анализ причин или комментариев.
   - По автору используется ID, а если он отсутствует — точное имя (возможны однофамильцы). Существующий блок «Возможные обращения автора» использует приблизительный поиск и не является историей организации.
   - Для организации требуется поле JSM Organizations с ID и распознаваемым именем поля; произвольное поле компании или имя автора не считается организацией. Если поле отсутствует или поиск недоступен, это показано явно. Заявки без заполненной организации не попадут в её выборку.
   - Результаты включают уже загруженные заявки и поиск Jira (до 500 на запрос), зависят от проектов, фильтров и прав доступа; полнота не гарантируется. При ошибке поиска остаются локальные данные с предупреждением. Подробности вопроса проверяйте в исходной заявке.

## 6. Связь с клиентом, определитель номера (Caller ID) и учёт времени Worklog

- **Прямой переход в мессенджеры**: рядом с каждым номером доступны кнопки **Telegram**, **Viber** и **WhatsApp** (а также распознаются `@username` Telegram в тексте).
- **Системный определитель клиента при входящем вызове (`Caller ID`)**:
  - Во вкладке *«Настройки» → «Включить системный определитель (АОН)»* назначьте `Help-CSL` приложением АОН Android (`CallScreeningService` — **не требует доступа к журналу вызовов**).

- **Автоматическое окно «📞 Итог звонка» (`Post-Call Worklog`)**:
  - Позвонили клиенту из карточки заявки → завершили вызов и вернулись в `Help-CSL` → приложение само предложит в 1 касание списать длительность звонка (`5 / 10 / 15 / 30 мин`) в `Worklog` Jira, надиктовать голосом `🎤` итог беседы или сразу завершить заявку.

## 8. Сетевой и админский комбайн: AnyDesk/RustDesk, Ping, порты, SSL, DNS и MAC-вендор

В карточке заявки блок **«Удалёнка и сеть»** автоматически извлекает из описания и комментариев:
- **9–10-значные ID AnyDesk / RustDesk / TeamViewer** (отсеивая телефонные номера) — копирование в буфер в 1 тап и прямой запуск мобильного клиента удалёнки;
- **IPv4-адреса и доменные имена** клиента;
- **MAC-адреса** (`D4:CA:6D:...`, `0050.56...`) с мгновенным офлайн-определением производителя оборудования (`MikroTik`, `Cisco`, `Ubiquiti`, `TP-Link`, `Keenetic/ZyXEL`, `Huawei`, `HP`, `Dell`, `Lenovo`, `Hikvision`, `Dahua`, `Synology`, `Kyocera`, `VMware`, `Proxmox` и др.).

По нажатию на найденный хост или кнопку **«Ping / Порты»** запускается комплексная проверка:
- **Проверка доступности системы** с задержкой в `мс`: Java `isReachable` может использовать ICMP или TCP Echo в зависимости от ОС и прав; отсутствие ответа не доказывает отказ узла;
- **Проверка 6 ключевых TCP-портов** (`80 HTTP`, `443 HTTPS`, `3389 RDP`, `22 SSH`, `8291 MikroTik WinBox`, `445 SMB`);
- **HTTP и HTTPS**: отдельные запросы `HEAD /` без перехода по перенаправлению на порты 80 и 443, если соответствующий TCP-порт ответил. Полученный код (включая 4xx/5xx) означает ответ, а не исправность приложения; запрос может использовать настройки прокси/резолвера системы;
- **TLS 443 и сертификат**: отдельное рукопожатие с проверкой цепочки доверия и имени по настройкам среды; при успехе показываются CN, УЦ и дата окончания. При ошибке TLS сертификат не оценивается: это может быть недоверенный, просроченный или не совпадающий с именем сертификат, а также другая ошибка TLS. Проверка отзыва сертификата не гарантируется;
- **DNS-адреса** в автоматической диагностике узла определяются системным резолвером устройства; приложение не отправляет MX/TXT/NS на публичные DoH-серверы. Системный резолвер может использовать внешний DNS в соответствии с настройками устройства и сети.

В карточке узла и отчёте выводятся отдельные этапы DNS, TCP, TLS, HTTP и HTTPS с причинами пропуска. Проверка TCP касается только выбранного адреса и портов; пользовательский порт проверяется как TCP, но TLS/HTTP для него отдельно пока не проверяются. Для фонового списка узлов HTTP/HTTPS отключены, часть портов может быть пропущена, а сертификат может отображаться из кэша до 6 часов — эти ограничения отмечены в результатах. Уведомление «нет ответа» не доказывает, что узел отключён. Адреса в URL HTTP/HTTPS могут разрешаться повторно и отличаться от адреса прямой TCP/TLS-проверки; учитывайте прокси и балансировку.

### Ручная проверка DNS

В «🛠 Инструменты» → «🌐 DNS» введите имя и IPv4 корпоративного DNS; при необходимости укажите второй IPv4 для сравнения. Выберите A, AAAA, MX, TXT, NS или AD SRV и подтвердите отправку **перед каждым запросом**. AD SRV запрашивает `_ldap._tcp.dc._msdcs.<домен>`; результат не доказывает здоровье контроллера. Проверка отправляет незашифрованные DNS-запросы по UDP на порт 53, при обрезанном ответе повторяет по TCP к тому же серверу. Изменения сетевых настроек и автоматического выбора публичного сервера нет. Не вводите внутренние имена вместе с публичным DNS без разрешения: имя получит каждый указанный сервер. Разные ответы могут быть нормой при split DNS; тайм-аут не доказывает отсутствие записи. Результаты можно скопировать; проверьте содержимое перед пересылкой.

- Как только связь с сервером Jira восстанавливается, фоновая служба `JiraMonitorService` автоматически синхронизирует всю очередь.

## 13. Безопасность: шифрование, вход по отпечатку пальца и досье клиентов

- **Аппаратное шифрование**: логин, пароль / API-токен и локальные заметки хранятся в `EncryptedSharedPreferences` на базе Android Keystore (`AES256-GCM`).
- **Биометрическая блокировка (`Biometric Lock`)**: при включении в *«Настройках»* приложение запрашивает отпечаток пальца, распознавание лица или системный PIN после сворачивания более чем на 2 минуты.
- **Локальное «📋 Досье клиента»**: в каждой карточке заявки можно сохранить постоянную памятку по конкретной организации (*провайдер, статический IP, где ключ от серверной, внутренний номер бухгалтерии*) — она автоматически отображается во всех будущих тикетах этого клиента и в баннере определителя номера.

## 14. Вкладка «В ремонт» — учёт техники, поступившей на ремонт

В нижней панели навигации расположена вкладка **«В ремонт»** со счётчиком активных устройств в мастерской:

1. **Как занести технику в ремонт**:
   - Нажмите **«+ Принять»** в шапке вкладки *«В ремонт»*;
   - Либо отсканируйте камерой штрихкод `S/N` в строке поиска — если устройство ещё не занесено, приложение сразу предложит создать карточку с этим `S/N`;
   - Либо внутри любой заявки Jira нажмите **«🔧 Занести технику во вкладку „В ремонт“»** — карточка приёмки автоматически заполнится организацией/клиентом, телефоном, ключом тикета (`CSL-…`) и описанием неисправности, а в саму заявку Jira (по галочке) добавится внутренняя заметка с номером приёмки `REM-…`.
2. **Карточка оборудования и автосправочник «Клиент / Организация»**:
   - В поле **«Клиент / Организация»** автоматически подгружается список всех организаций и клиентов из Jira Helpdesk (организации JSM `/rest/servicedeskapi/organization`, кастомные поля *Organizations/Компания* и авторы клиентских тикетов, без `zabbix`/ботов): при нажатии `▼` или вводе первых букв открывается живой поиск с автоподстановкой известного телефона клиента. Каждый введённый вручную новый клиент автоматически сохраняется и дополняет справочник (в том числе синхронизируясь с коллегами);
   - Тип техники (*Ноутбук, ПК, Принтер/МФУ, Сервер/СХД, Сетевое, ИБП, Монитор*), модель и серийный/инвентарный номер (со сканером штрихкодов `📷` и голосовым вводом `🎤`);
   - Быстрые чипы **комплектности при приёме** (*Блок питания / ЗУ, Кабель 220В, Сумка, Мышь/Донгл, Картридж, Коробка, Без комплекта*), внешнее состояние, полка хранения (*например, Стеллаж А-2*) и ответственный инженер;
   - Заявленная неисправность и блок хода диагностики / заказанных запчастей / выполненного ремонта.
3. **Этапы, быстрые переходы и аудит удалений («Удалённые»)**:
   - Подвкладки **«В работе»** (*Принято → Диагностика → В ремонте*), **«Ждёт ЗЧ»**, **«Готово»**, архив **«Выдано»** и раздел **«Удалённые»**;
   - **Никакая позиция не пропадает бесследно**: при нажатии удаления карточка перемещается в подвкладку **«Удалённые»**, где фиксируется **кто удалил** (ФИО и логин инженера), точные дата и время, причина удаления (по желанию), а при ошибочном удалении доступна кнопка **«↩ Восстановить»**;
   - Кнопки мгновенной смены этапа прямо на карточке + кнопки связи с клиентом в 1 тап (**📞 Позвонить**, **Telegram**, **Viber**, **WhatsApp**) и кликабельный переход в связанную заявку `CSL-…`.
4. **PDF-квитанция приёма и PDF-акт выдачи с подписью**:
   - Кнопка **«PDF»** на карточке формирует фирменный A4-документ в стиле `csl.by` (*«Квитанция о приёме техники в ремонт»* или *«Акт выдачи из ремонта»*) с возможностью росписи клиента пальцем на экране, отправки на печать / в мессенджер или прикрепления к заявке Jira.
5. **Офлайн-работа и командная синхронизация**:
   - Все записи мгновенно сохраняются локально (доступны даже без интернета) и автоматически синхронизируются между всеми инженерами через служебный реестр Jira (`[HELPCSL_REPAIR_REGISTRY_ROOM]`, полностью скрытый из клиентских очередей и уведомлений).

## 15. Настольная версия Help-CSL для Windows 10/11 (`setup.exe`)

Наряду с Android-приложением доступна полноценная настольная версия **Help-CSL для Windows 10 / 11 (x64)** в виде самодостаточного инсталлятора **`setup.exe`** (в каждом выпуске [GitHub Releases](https://github.com/zigorminsk-debug/Helpdesk/releases)).

1. **Установка без Java и без прав администратора**:
   - Скачайте `setup.exe` и запустите мастер установки: среда исполнения уже встроена внутрь пакета (`jpackage` app-image + Inno Setup 6), поэтому устанавливать Java на рабочий ПК не нужно, а установка в профиль пользователя (`%LOCALAPPDATA%\Programs\Help-CSL`) работает даже без прав локального администратора Windows.
   - В мастере можно отметить **ярлык на Рабочем столе** и **автозапуск при входе в Windows** (`--minimized` сразу в системный трей).
2. **Системный трей Windows и всплывающие баннеры по графику РБ (`09:00`–`17:30`)**:
   - При закрытии окна (`✕`) программа сворачивается в системный трей Windows с иконкой #20 и счётчиком активных заявок.
   - В рабочие часы Республики Беларусь (`09:00`–`17:30`, с учётом официальных праздников и переносов Совмина РБ) при приходе новой клиентской заявки справа внизу над часами появляется фирменный всплывающий баннер `csl.by` с кнопками **«▶ В работу»** и **«Открыть»**, звучит полифонический сигнал и (при включении) голосовое чтение Windows SAPI TTS. В нерабочее время и выходные РБ — тихий режим без звука и баннеров.
3. **Инженерные суперспособности Windows в карточке заявки**:
   - **1-клик AnyDesk и RustDesk**: автоматический запуск установленного `AnyDesk.exe` / `rustdesk.exe` с мгновенным подключением к распознанному ID клиента (и копированием ID в буфер обмена);
   - **1-клик RDP (`mstsc.exe /v:host`), SSH-терминал и сетевая диагностика** (TCP-порты, SSL, DNS, OUI MAC-вендор) по распознанным IP и доменам;
   - **SIP-софтфон (`tel:`) и мессенджеры**: звонок одним кликом через MicroSIP / 3CX / PhonerLite и открытие чатов `Telegram`, `Viber`, `WhatsApp` по нормализованным номерам `+375` и `+7`;
   - **Вставка скриншотов `Win + Shift + S` в 1 клик**: нажмите `Win + Shift + S`, выделите область экрана и нажмите в карточке заявки **«📸 Вставить скриншот (Win+Shift+S)»** — снимок сразу прикрепится в Jira без сохранения промежуточных файлов!
4. **Синхронизация «В ремонт», печать PDF А4, «Чат» и QR-спаривание со смартфоном**:
   - Вкладка **«В ремонт»** на ПК поддерживает ручные USB-сканеры штрихкодов `S/N`, единый справочник **«Клиент / Организация»** из Helpdesk, аудит **«🗑 Удалённые»** (кто удалил + `↩ Восстановить`) и мгновенное формирование/печать кириллических квитанций и актов А4 PDF.
   - Кнопка **«📲 QR»** в верхней панели выводит на монитор зашифрованный код `HELPCSL1:` — достаточно навести камеру смартфона в Android-версии Help-CSL, чтобы за 3 секунды перенести все настройки сервера, фильтра и токен между ПК и телефоном.
   - Встроенное автообновление проверяет свежий выпуск на GitHub Releases, скачивает новый `setup.exe` и запускает обновление поверх без потери зашифрованных настроек (`%APPDATA%\Help-CSL\state.enc`).

В Windows рабочие окна открываются на доступную область монитора, оставляя панель задач. Закрывайте их крестиком или Esc. Вкладки инструментов переносятся на следующую строку.
